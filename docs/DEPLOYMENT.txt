DEPLOYMENT — updated 2026-11-26
Live: https://bill-please.netlify.app/
Repository: https://github.com/Katsys7/bill-please

Keep the existing Netlify project connected to main, on the Free plan.
Base directory blank; build command blank; publish directory site.
The committed netlify.toml selects Node 22, bundles netlify/functions, and
rewrites /b/ID to the recipient page. Netlify installs package-lock.json.
No separate database account, API keys or paid plan is required.

NEW SHORT-LINK BACKEND
@netlify/blobs is the only runtime dependency. The deployed Function receives
its storage context automatically. Completed bills are persisted in the
site-wide store bill-please-shared-v1. Keep that name stable across deploys.
Old bill.html#... links work without storage. New /b/ID links require this
function/store; deploying only site/ by drag and drop will not deploy them.
Use the connected Git repository to deploy the complete project.

POST /api/bills creates an immutable snapshot and returns a 16-character ID.
GET /api/bills?id=ID reads it. There is no public list/delete/edit operation.
Anyone with the link may read that completed bill. Draft edits stay local.
The server validates and caps requests. Keep Netlify Free's hard cap; it can
pause service if included usage is exhausted, but requires no automatic payment.

AFTER A PUSH
Open Netlify > your project > Deploys. The commit should receive a successful
production deploy and show Published. Refresh the site after it finishes.
Test Create, Copy link to share, PREVIEW, and SAVE on a synthetic bill. Open the
short /b/ID link on another device. Verify it still works after another deploy.
If storage fails, SAVE still works and sharing shows a retry message.
Check Netlify Function logs for operational errors, never log bill contents.

IF THE SITE IS PRIVATE
Choose Make public, or Project configuration > General > Visitor access >
Project visibility > Public. Keep the free netlify.app address.

LOCAL DEVELOPMENT
Node 22+, npm ci, npm test. Full backend preview: Netlify CLI dev against the
site (sign in yourself if needed). Python tools/serve.py provides UI-only
preview, not persistent short links. Keep local credentials out of Git.

OTHER HOSTS
The supplied Vercel static config does not provide the short-link backend.
Port that backend deliberately before changing hosts. Keep existing URLs stable.
