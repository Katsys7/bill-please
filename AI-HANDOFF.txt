SHARE LINKS — IMPORTANT BEHAVIOR CHANGE
New links use https://bill-please.netlify.app/b/ID, where ID is 16 URL-safe random
characters (96 random bits). No bill text is encoded in the copied short link.
On the ready page a completed bill is sent to POST /api/bills once, cached per
last bill in localStorage, and reused by Copy and Preview. Draft edits are never
uploaded. A recipient loads its immutable snapshot with GET /api/bills?id=ID.
The bill is now stored in Netlify, unlike the previous entirely client-only
version. Anyone who has a short link can read its bill; IDs are not logins.
Store name: bill-please-shared-v1. Use getStore, not getDeployStore: data must
survive deployments. No expiry, listing endpoint, overwrite, or deletion UI.
Do not casually rename/delete this store or invalidate existing links.
POST enforces same-origin browser requests, JSON, 24 KiB body cap, schema checks,
12 item maximum, random IDs and conditional writes. Platform rate limit is 30
requests per minute per IP+domain. Never log bills or Netlify credentials.
A missing/broken service shows a retry message, never silently copies a huge URL
or fabricates a short link. SAVE remains usable independently of sharing.
New API requests time out after 15 seconds.

BACKWARD COMPATIBILITY
Old bill.html#BASE64URL links still decode locally, including missing location,
older color names, and notes up to 400 characters. New editor notes are limited
to 100 with a live counter. Preserve this distinction. Draft key remains
bill-please-draft-v2; final key remains bill-please-final-v2. Share cache key is
bill-please-share-v1. normalize() and complete() live in bill-data.js and are
shared between browser and function; retain the same validation rules.
The new /b/ paths need Netlify's internal rewrite plus bill.html's root base URL
so fonts, images and scripts resolve correctly from nested paths.

RUN / DEPLOY
UI-only preview: python3 tools/serve.py --port 4173 (or an unused port).
Short links require the Netlify backend; the plain Python server cannot provide
them. For full local integration, use Node 22+, npm ci, and Netlify CLI dev
against your site; sign in yourself if it requests access.
Offline API tests: npm ci then npm test. No live bill data is required.
Netlify installs the locked dependency and bundles the function automatically.
Publish directory site, base directory blank, build command blank. Keep main
connected and automatic publishing enabled. No manual environment variables
or separate storage account are needed for the SDK in deployed Functions.
Stay on Free: Functions/Blobs consume included hosting credits; the Free hard
cap can pause service, so this is not unlimited traffic or unlimited storage.
Do not enable paid upgrades or auto recharge. No AI credits are needed to run.
Vercel/GitHub Pages can still serve the frontend, but these new short links need
the Netlify function/store or an explicitly approved replacement implementation.
